## Найденные проблемы (сгруппированы по приоритету)

### 🔴 КРИТИЧНЫЕ — блокируют работу с приложением

#### 1. Координаты проекта пропадают из формы после сохранения
**Симптом:** ставишь точку на карте через 📍, сохраняешь проект, открываешь на редактирование — поле lat/lng пустое.  
**Диагноз:** форма не подтягивает `site_point` из БД при re-render. В БД координаты есть (проверено скриптом `check-sites.mjs`). Это **чисто UI-баг**.  
**Файл:** `src/components/manager/ProjectsPage.tsx` или `ProjectDetailPage.tsx`  
**Сложность:** малая

#### 2. Форма создания проекта пишет ставку в поле радиуса
**Симптом:** ты ввёл "200" в поле «Почасовая ставка» → в БД `radius_m=200` у проекта (должно быть 75).  
**Диагноз:** перепутаны name attributes на inputs или неправильный маппинг в handleSubmit.  
**Файл:** `src/components/manager/ProjectsPage.tsx` (форма создания)  
**Сложность:** малая

#### 3. 3 кнопки загрузки в проекте: Фото / Видео / PDF — отсутствуют
**Симптом:** на детальной странице проекта нет отдельных кнопок для загрузки фото, видео, PDF чертежа.  
**Диагноз:** возможно есть одна общая кнопка, или компонент скрыт условием.  
**Файл:** `src/components/manager/ProjectDetailPage.tsx`  
**Сложность:** средняя (нужна UI-секция + валидация типов)  
**Критичность:** высокая — без этого на стройке нельзя работать

#### 4. Мобильный login сломан
**Симптом:** на телефоне PIN-pad не реагирует на тап, либо появляется двойное поле, либо ввод не синхронизируется с React state.  
**Диагноз:** 3 итерации фиксов не помогли. Проблема глубже — нужно переделать login с нуля по образцу старого приложения (`index_v4.9.html`), где был просто `<input type="password">`.  
**Файл:** `src/app/(auth)/login/page.tsx`  
**Сложность:** средняя (нужен откат текущих фиксов + чистая реализация)

### 🟡 СЕРЬЁЗНЫЕ — нарушают функциональность, но можно обойти

#### 5. Микрофон ломает Windows Audio Service
**Симптом:** после использования голосового ввода в нашем приложении микрофон начинает тупить во ВСЕХ Windows-приложениях, до перезагрузки.  
**Диагноз:** в `useVoice.ts` после `onerror`/`onend` не вызывается `recognition.stop()`, не обнуляется `recognitionRef.current`. Каждая сессия оставляет висящий SpeechRecognition объект. Это системная утечка handles микрофона.  
**Файл:** `src/lib/hooks/useVoice.ts`  
**Сложность:** малая (5 строк cleanup в onend/onerror)

#### 6. Голосовой ввод отваливается после паузы
**Симптом:** начал диктовать — сказал 2 слова — замолчал на секунду — микрофон сам остановился.  
**Диагноз:** `recognition.continuous = false` (строка ~82 useVoice.ts). Надо `true`.  
**Сложность:** тривиальная

#### 7. Голосовой ввод жёстко настроен на английский
**Симптом:** русский не распознаётся, либо результаты кривые.  
**Диагноз:** `recognition.lang = "en-US"` хардкод. Надо брать из i18n locale (у тебя стоит ru).  
**Сложность:** тривиальная

#### 8. Дубликаты проектов "Home" и "Дом."
**Симптом:** в БД два проекта с одинаковыми координатами и радиусом (ты создал или переименовал, остался дубль).  
**Решение:** удалить "Home", оставить "Дом." Или наоборот — какой решишь сохранить.  
**Сложность:** делается через UI один клик после того как архивация работает.

## Архитектурные наблюдения (хорошее и плохое)

### ✅ Хорошее
- **Миграции в одной папке, пронумерованы** — легко воспроизводить состояние БД
- **`00099_wash_and_reset.sql`** — есть «красная кнопка» полного сброса
- **RLS-политики — на уровне БД, не в коде** — безопаснее чем гадать в TypeScript
- **Единая функция `is_manager()`** управляет всеми manager-tier RLS — одно место, одна правка (что мы уже сделали, мигр. 00013)
- **42/42 vitest тестов** — есть фундамент
- **`preview-data.ts` изолирован через `AUTH_BYPASS_ENABLED`** — при отключённом bypass все три entry points (`manager-data`, `worker-data`, `ai/data`) корректно идут в БД
- **Продуманная RBAC-матрица** (`docs/permissions.md`)

### ⚠️ Слабые места
- **`AUTH_BYPASS=true` как режим разработки оказался опасен** — год маскировал несостыковки БД↔код. Рекомендация: после этой волны **удалить механизм AUTH_BYPASS полностью** или переделать его чтобы он вообще НЕ читал preview-data, а просто не требовал сессии (без подмены данных)
- **Нет e2e тестов** — только unit. Playwright/Cypress для критичных сценариев (login, clock-in, create project) окупит себя
- **Мобильный UX не тестировался** — custom numpad на login, отсутствие `touch-action` в нескольких местах, GPS consent модалки не проверены на iOS
- **Backup стратегия не формализована** — перед каждой большой миграцией нужен `pg_dump`, сейчас делается «на ощущение»
